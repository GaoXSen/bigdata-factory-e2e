# E2E 测试报告规范

## 生成规则

- 每次执行使用独立 run ID；至少包含日期和时间，不能把不同执行结果混在同一个汇总中。
- 报告放在项目 `temp/`；HTML 报告、截图、视频和 trace 放在 Playwright 配置指定目录。
- 每个用例完成后记录真实 `testInfo.status`，包括 passed、failed、skipped、fixme 和 timedOut。
- 报告不得写入密码、令牌、完整数据库连接串或敏感页面截图以外的秘密信息。
- 失败证据必须可定位到用例文件、行号和 artifact 路径。
- 环境阻断不与服务/页面测试结果混写；由 `e2e/utils.ts` 单独生成 `temp/环境阻断报告-{run_id}.md`。

## 报告模板

```markdown
# E2E 测试报告 — {run_id}

## 执行信息
- 执行时间：{start} ~ {end}
- 执行命令：{command}
- 浏览器：Playwright Chromium {version}
- 目标入口：{base_url_or_entry_url}
- 执行机器/网络：{machine_and_network_note}
- 账号角色：{role_only}

## 汇总
- 注册用例：{n}
- 实际执行：{n}
- 通过：{n}
- 失败：{n}
- 跳过：{n}
- fixme：{n}
- 环境阻断：{n}
- 清理失败：{n}

## 失败分类
- 登录/网络：{n}
- 选择器或页面结构：{n}
- 数据前提缺失：{n}
- 业务行为缺陷：{n}
- 自动化脚本缺陷：{n}

## 执行详情

### {用例 ID} {用例名} — {passed/failed/skipped/fixme/blocked}
- **用例文件**：{absolute_or_project_relative_path}:{line}
- **耗时**：{duration}
- **前置条件**：{data_and_role_preconditions}
- **关键步骤**：
  1. {action} ✓
  2. {action} ✗ — {error_summary}
- **页面断言**：{actual_vs_expected}
- **截图**：{path_or_none}
- **Trace/视频**：{path_or_none}
- **控制台异常**：{none_or_summary}
- **清理结果**：{done/failed/not_applicable}
- **建议**：{next_action}

## 跳过与环境阻断
- {case}: {explicit_reason_and_missing_precondition}

环境阻断报告单独记录网络、登录、账号、FTP/SFTP、数据库、Hive、环境数据和浏览器执行资源问题。环境恢复后应使用新的 run ID 重跑，不把旧环境阻断直接改写成服务缺陷或通过。

## 后续动作
1. {owner} — {action}
```

## 质量要求

报告中的“通过”必须来自真实测试状态；步骤详情不能覆盖最终失败。未配置的 DB/FTP/角色只能记为跳过或环境阻断，不得计入通过。旧报告如果需要保留，应归档后再生成新 run 报告。
