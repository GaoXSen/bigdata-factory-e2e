# E2E 测试问题优化与解决记录

> 用途：记录跨网站、跨项目可复用的 Playwright E2E 问题和处理模式。
> 
> 边界：不记录测试网址、账号、密码、Token、数据库连接串、FTP 地址或当前项目的环境专属名称；这些内容只放项目自己的环境清单和未纳入版本控制的本地配置中。

## 1. 测试状态与报告

### 1.1 “跳过”掩盖了真实覆盖率

现象：大量用例使用 `test.skip`/`test.fixme`，报告看起来干净，但无法知道是未执行、环境阻断还是页面真的通过。

处理：

- 完整报告模式先静态检查 `test.skip`、`test.fixme`、`describe.skip`、`test.only` 等标记，数量应为 0。
- 环境缺失仍让用例进入执行路径，在明确的前置检查处抛出可识别的环境阻断错误。
- 主报告统计 passed/failed/timedOut/skipped；环境阻断另写独立 Markdown，不把阻断改成通过。
- “样本模式”可以只执行可用用例，但必须通过单独命令或变量显式选择，不能混入完整报告。

### 1.2 清理失败覆盖主失败

现象：创建或写入失败后，`finally` 中删除动作再次失败，最终只看到“删除失败”，丢失了真正的创建/写入原因。

处理：使用 `primaryError` 和 `cleanupError` 分开记录；只有确认资源创建成功后才标记需要清理。最终优先抛出主错误，同时把清理错误附加到报告。

### 1.3 假通过

常见原因：旧 toast、旧结果页签中的 `true`、视频里看起来点击完成、固定等待结束、空列表没有报错、异步下载尚未完成。

处理：

- 成功提示限定在当前可见消息容器内，并同时验证业务状态、结果行、跳转或按钮状态。
- SQL/查询逐条确认当前结果页签，先识别错误文本，再判断成功值；不能复用上一条 SQL 的结果。
- 下载使用 `page.waitForEvent('download')`，并核对文件存在、文件名/扩展名，按需求核对大小或内容。
- 长任务使用页面明确完成状态或轮询结果；等待时间只是上限，不是通过条件。
- 通过用例在交付前抽查视频/trace，确认未因自动结束或旧结果误报。

## 2. 页面结构与定位

### 2.1 顶部导航或页签显示不全

现象：页面首屏能看到部分 tab，剩余 tab 在 `...`/“更多”中；直接按文本定位会报不存在。

处理：公共导航/页签工具按以下顺序执行：

1. 收集当前可见 tab。
2. 查找并展开 `...`、`···`、`更多`、左右滚动或折叠入口。
3. 重新读取 DOM/无障碍树。
4. 在当前可见容器内定位目标 tab，并断言选中状态或页面内容。

不要把当前视口可见的 tab 数量当作功能总数，也不要在每个 TS 中各写一套“更多”展开逻辑。

### 2.2 父菜单、叶子菜单和同名节点

现象：点击父菜单只完成了路由切换，没有进入叶子页；同名节点在隐藏模板、固定列或折叠菜单中重复渲染。

处理：记录完整菜单路径；父菜单展开和叶子菜单点击分开处理。定位时使用 `:visible`、角色和当前菜单容器，点击后同时复核 URL 与页面关键内容。不要默认取第一个匹配节点。

### 2.3 固定列和操作列

现象：Ant/Element 表格把名称列或操作列拆成固定表格和主体表格，按普通行里的第一个“编辑/详情”可能点击到隐藏副本或被遮挡。

处理：先按业务名称找到当前可见行，再优先在对应固定列容器中找按钮/链接；点击后等待 URL、弹窗、标题或内容变化。必要时把“行定位”和“操作定位”封装成公共方法。

### 2.4 分裂按钮和二次选择

现象：点击“新建”后出现数据库/类型下拉，脚本误把菜单项当成表单按钮，或表单还没加载就开始填字段。

处理：点击入口后先选择当前目标项，再等待表单关键控件（如保存、建表按钮）可见；记录实际选中的文本。不要用同名文字的全局 `getByText()` 代替当前菜单容器。

### 2.5 并行登录导致的偶发入口失败

现象：多个浏览器进程同时登录时，测试在几秒内都报“登录后主导航未加载”，页面本身并不一定持续不可用。

处理：把登录/公共导航视为共享资源；先做一次单进程登录检查，再并行只读任务。修改型任务按资源锁串行，报告目录分开。网络抖动时保留有限次数的登录重试和截图，不要让多个线程无限重试同一个入口。

## 3. 表单、下拉和弹窗

### 3.1 长下拉选项被滚动层拦截

现象：选项肉眼可见，但 Playwright 报另一行或弹层拦截 pointer events；反向遍历选项时固定 `nth()` 还可能命中动画中的节点。

处理：只遍历当前可见选项；匹配文本后 `scrollIntoViewIfNeeded()`，再点击。若已确认是当前弹层且没有可替代的语义定位，可使用 `click({ force: true })`，但不能用 force 掩盖错误容器或遮挡层。

### 3.2 级联字段遗漏必填项

现象：表单能填入表名和部分字段，但保存/建表没有成功；页面快照显示带 `*` 的 `schema`、主题域、负责人或安全等级仍为空。

处理：根据真实页面快照建立必填字段清单，逐项填写并验证选中值。标签匹配兼容大小写、中文/英文和冒号差异；级联字段必须等待上一级完成后再选下一级。不要因为下拉选项多或定位困难而省略必填字段。

### 3.3 带箭头的空控件优先按下拉框处理

现象：表单中的字段没有可直接填写的 input，但控件带向下箭头或渲染为 `role="combobox"`；脚本只填写了文本框和单选框，提交后弹窗仍保持打开，最终因没有成功提示而超时。典型情况是“是否敏感”字段未选择，选择“敏感”或“不敏感”均可正常创建。

处理：提交前扫描当前弹窗内的必填项和空的 Select/combobox：点击控件，读取当前可见下拉选项，选择一个合法选项，回读控件文本确认已选。选项值不影响本条用例时可以选择第一个合法值，但不能把空值当作默认值；只有展开后确实没有选项，才归类为环境或页面阻断。

### 3.3 弹窗已打开却重复点击背景按钮

现象：点击“引用数据元/选择数据元”时报背景按钮被弹窗内容拦截；实际上第一次点击已经打开了弹窗。

处理：操作前先判断目标 dialog/drawer 是否可见。已打开时直接在当前弹窗内定位表格、复选框和确定按钮；表格行和按钮不要从整页查找。

### 3.4 组合配置区不能只填首字段

现象：页面把一个业务配置拆成多个连续控件，例如“数据生命周期配置”同时包含生命周期、操作类型、是否确认、确认周期和排除分区；脚本只填写上方基础信息和字段，配置区仍全部为空。

处理：把组合区域当成一个完整业务对象处理，按已建数据的编辑页面确定合法组合，逐项选择每个下拉值并设置相关单选项；新建与编辑复用同一个配置 helper。执行后应在快照或结果页确认每个控件已有选中值，不能只验证保存按钮可点击。

### 3.5 级联数据源不能盲选第一项

现象：数据源类型下拉第一项可能是 DM，但页面没有保存的 DM 数据源；脚本用 `ArrowDown` 或“首项”继续选择，后续数据源、数据库、Schema 和数据表为空，最终造成 API 创建失败或留下无效测试选择。

处理：逐级读取当前页面的可见选项，遍历“数据源类型 → 已保存数据源 → 数据库 → Schema → 数据表”的完整链路；只有整条链路都有真实选项才提交。某个类型没有数据源时切换下一个类型，不写死类型名称，也不把空列表当作可用数据。

### 3.6 密码校验提示出现时不能强制点击确定

现象：用户管理新增用户时，空密码、短密码或简单密码会在密码输入框下方即时显示校验提示，同时“确定”按钮不可提交或被表单校验状态阻断。脚本如果无条件等待并点击“确定”，会把正确的前端拦截误报为脚本失败。

处理：异常输入用例先读取密码字段下方的可见校验提示；出现“不能为空、长度、字符、格式、至少”等密码校验信息时，直接判定该异常分支拦截正确，不再寻找或点击“确定”。只有没有校验提示且提交按钮可用时，才点击提交；如果提交成功，应判定密码校验不合格。组织/级联选择器若有独立的“确定/取消”区域，先确认级联选择，再提交主表单；不要用 Escape 盲目关闭，避免把整个新增弹窗一起关掉。

补充：密码规则通常在 `blur` 后异步触发，固定等待 300ms 可能早于页面更新。脚本应在失焦后轮询密码字段的可见错误提示，给出约 4 秒上限；匹配“请输入新密码”这类字段占位/标签文本时不算校验通过，必须匹配“不能为空、长度、格式、非法字符”等规则性提示。

### 3.7 固定表格的省略文本和重复导航

现象：用户创建成功后，列表中的用户名以省略号显示，页面同时渲染固定列和主体列的重复 DOM；脚本使用全局文本的 `.last()` 可能取到隐藏副本。异常值循环在已经处于目标路由时再次点击顶层菜单，也可能因为当前页面没有该顶层节点而提前失败。

处理：列表断言定位当前可见行，使用可见行的 `toContainText`，不要直接断言全局文本节点可见；循环用例进入页面前先判断当前 URL 和关键按钮，已在目标页时直接复用，不重复点击菜单。这样既能验证真实列表数据，也能保证所有异常输入分支继续执行。

### 3.8 下拉框未收回、异常值复用弹窗与异步反馈

本轮新增确认的通用问题：

- 级联选择器或下拉框选中值后仍保持展开，浮层会遮挡新增/保存/确定按钮。选择完成后要确认下拉浮层已关闭；若页面有独立的“确定/取消”区域，先点击该区域完成选择，再移动鼠标到空白位置并确认主表单按钮可见。
- 同一表单的异常值校验不需要每个值都重新打开弹窗、创建对象或清理对象。打开一个新增弹窗，填写一次公共字段，然后依次替换同一字段的异常值，执行“填写 → 失焦 → 等待提示 → 记录结果”；全部校验完成后统一取消弹窗，不提交脏数据。
- 页面校验可能由 `blur`、`change` 或 debounce 异步触发。固定等待几百毫秒可能早于页面反馈，导致脚本报告“未显示提示”，但视频中已经出现提示。应在触发失焦后轮询字段附近的可见错误提示，并设置合理的单字段上限；匹配规则要识别“不能为空、长度、格式、非法字符”等规则性文案，不能把普通占位提示当作校验结果。

适用范围：用户、数据源、数据表、接口、文件接入等所有包含下拉字段和异常输入矩阵的表单。

### 3.9 不同测试类型必须拆成不同用例

现象：同一个编号同时写“正常流程+异常值/边界”，生成脚本后正常创建流程、异常校验和清理逻辑互相影响，结果也无法判断究竟是哪类测试失败。

处理：一个用例编号只保留一个测试类型、一个明确目标和一个 TS 文件。正常流程、异常值/边界、权限、兼容性、性能等必须拆成独立编号；允许用例数量增加，但禁止在同一用例中混合不同测试类型。异常值矩阵可以在同一个“异常值/边界”用例内循环验证同一字段，但不能和正常提交流程混放。

### 3.10 Windows 批处理脚本必须使用 CRLF

现象：`.cmd` 文件使用 Unix 的 LF 换行时，Windows `cmd.exe` 会把注释、`for` 块和括号拆成多条命令，出现“不是内部或外部命令”“) was unexpected”等错误，甚至在进入 Playwright 前丢失环境变量。

处理：Windows 执行脚本保存为 CRLF；项目专用脚本直接使用固定项目目录并允许 `TEST_DIR` 覆盖，避免嵌套 `for (...)` 扫描和编码导致的批处理解析问题。Playwright 参数继续通过 `%*` 原样透传。

## 4. 编辑器和数据操作

### 4.1 Monaco 被普通 textarea 误命中

现象：SQL 看起来没有执行，实际文本被填入描述字段或其他 textarea。

处理：优先使用 Monaco 的可访问 textbox 名称 `Editor content;Press Alt+F1`；填写后验证编辑器可见内容，执行后检查当前结果页签。不要使用 `textarea.first()` 这种未经页面校准的定位。

### 4.2 自建对象未登记导致查询被业务规则拦截

现象：SQL 建表/插入可能成功，但自助查询返回“数据表未接入/未登记”，直接查询不到刚建的表。

处理：这是业务前置或用例设计问题，不是定位问题。确认产品是否要求先通过数据工厂登记/接入表，再决定：

- 通过页面完整登记后再验证查询闭环；或
- 把用例改成“页面 SQL 写入成功 + 页面明确拒绝未登记表查询 + 清理成功”的规则验证，并在标题和报告中写清楚；
- 不要把没有查询到标记的数据误判为通过。

## 5. 失败分类和迭代顺序

每轮失败按以下顺序归类，避免在环境问题上反复改定位：

1. 登录、DNS、网络和页面入口。
2. 隐藏菜单、页签、弹窗、表格固定列和下拉定位。
3. 表单必填项、级联选项、编辑器和结果页签。
4. 测试数据、角色权限、FTP/SFTP/Hive/数据库等环境前置。
5. 页面实际行为与需求描述不一致，或产品业务规则阻断。
6. 结果有效性：超时、旧提示、空结果、下载未落盘或异常被吞掉。

每条修复都应有：失败截图/trace、原因分类、改动文件、最小回归命令和真实结果。连续两次证据表明是环境或业务前置时停止盲目改选择器，转为环境阻断或需求确认。

## 6. 并行执行注意事项

- 主线程统一拆分任务、合并公共工具改动、控制资源锁和最终回归。
- 不同 TS 可并行；共享账号、同一表/任务/权限状态、同一 FTP 目录和公共配置不能无锁并行写入。
- 每个并发进程必须有独立 `E2E_RUN_ID`、HTML 报告目录、结果目录和 Markdown 报告路径。
- Playwright `workers` 与 AI 子线程不是一回事；修改型用例在各自线程内默认 `--workers=1`。
- 机器或 VPN 资源紧张时，先减少并发进程；不要靠反复重试、无条件加长超时来掩盖资源问题。
