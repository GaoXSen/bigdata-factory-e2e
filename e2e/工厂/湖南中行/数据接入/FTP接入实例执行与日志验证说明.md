# FTP 接入实例执行与日志验证说明

## 适用范围

湖南中行环境的文件接入、FTP/SFTP 接入任务回归。正常执行类用例复用已建好的 `gs_test_` 任务；新建类用例只在需要验证向导和保存逻辑时创建一次独立任务。

## 已确认的页面流程

1. 进入“数据接入 → ftp文件接入 → 接入列表”。
2. 文件名筛选 `gs_test_`，按文件名、导入状态和操作列的相同行号定位任务。
3. 正常执行类用例点击同一行“执行”，确认提交成功。
4. 点击“查看实例”，进入“接入实例”列表。
5. 等待实例“接入状态”从“执行中”变为“执行成功/同步完成”。出现进度条或执行成功提示，不等于文件已真正落地。
6. 点击同一实例的“执行日志”，核对日志正文存在 DataX、执行完成、同步完成或成功等明确结果。

## 新建任务的关键规则

- SFTP 示例：协议 SFTP，地址 `192.168.76.110`，端口 `22`，目录 `/source`，账号密码认证。
- MySQL 目标固定优先选择 `192.168.76.110:13306/e2e_test`，数据库和 Schema 均为 `e2e_test`。
- 文件名规则按页面真实流程设置为“日期前分隔符 `_`、日期维度 `日`、日期偏移 `0`、后缀为空”，点击“预览文件名”后应为 `gs_test_YYYYMMDD`。
- 点击“数据预览”后再进入字段映射；“映射目标字段”是每行第一个可编辑输入框，不是目标字段描述。
- 目标字段必须合法且唯一。来源文件存在重复字段名时，正常用例需要改成唯一目标列名；重复、空值、数字开头和特殊字符另立异常用例。

## 通过判定

必须同时满足：

- 任务执行提交成功；
- 接入实例已生成；
- 实例最终状态为成功；
- 执行日志有明确完成结果；
- 需要验证数据时，再核对目标表实际数据或版本记录。

## 重跑原则

- 执行、实例、日志、日期预览类用例优先复用已有 `gs_test_` 任务，避免每轮重复新建同名任务。
- 新建任务用唯一任务名和目标表名；测试环境创建的夹具可保留供后续回归。
- 只操作本轮测试任务，不修改其他业务任务和远端非测试文件。
- 接入列表是固定列拆分表，不能在文件名表格行内直接寻找操作按钮；必须按相同行号映射操作列。
- “执行日志”可能打开独立页面/标签页，脚本需要切换到实际日志页面后再读取正文。
