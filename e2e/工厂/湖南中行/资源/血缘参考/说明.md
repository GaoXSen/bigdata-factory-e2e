# 血缘 Java 参考资料

本目录只保存血缘 SQL 和断言参考，不作为 Playwright 测试脚本执行，也不自动连接数据库。

## 文件

- `GbaseProcedureLineageTest.java`
  - GBase 8a 生产级匿名块大 SQL。
  - 覆盖 DELETE、INSERT、WHERE EXISTS、临时表、聚合、JOIN、CALL、异常处理和多字段投影等复杂血缘场景。
- `ProcedureLineageTestMain.java`
  - 存储过程血缘场景样例。
  - 覆盖变量链、常量链、IF 分支、游标、SELECT INTO、CALL、嵌套块、PREPARE 动态 SQL、UPDATE/DELETE 条件变量、UNION/CTE、VALUES、WHILE、handler、OUT 参数和 CASE。
- `LineageTestInterface.java`
  - Java 血缘分析器断言接口。
  - 作为后续 Playwright 页面断言设计的语义参考。

## 页面自动化转换口径

1. 大 SQL 应配置到真实存在的表和任务中；SQL 中的表名、Schema、字段不能直接使用示例占位名。
2. 先确认来源表、目标表在数据地图中存在，并且目标表可以进入表管理编辑任务调度。
3. 按“表管理列表下线 → 编辑 → 任务调度保存 → 回到列表上线 → 表查询 → 表详情 → 数据血缘”完成前置闭环。
4. 表级血缘验证来源表、目标表和唯一关系；字段级血缘验证源字段、目标字段和关系类型。
5. 复杂 SQL 需要记录解析结果或明确的“未解析/动态 SQL”提示，不能仅凭页面出现进度或按钮就判定成功。
6. 重复节点、重复关系、错误节点和动态 SQL 的处理结果应明确记录；不能用页面上任意首个匹配元素代替精确断言。

## 断言语义摘要

- 表节点：按 Schema、表名精确匹配，必须恰好一个，并核对节点类型和别名数量。
- 列节点：按所属表和列名精确匹配，必须恰好一个，并核对列角色和别名数量。
- 表级边：按源表、目标表匹配，必须恰好一条。
- 列级边：按源列、目标列和边类型匹配，必须恰好一条。
- 变量列：单独统计 `VARIABLE` 角色数量。
- 失败信息：应保留当前实际节点、边、告警和页面状态，便于区分脚本定位问题、环境前置缺失和真实业务问题。
